# 开发规范

> 本文件为项目代码规范详细版。**权威源为 AGENTS.md「强制规范」与「基础代码规范」章节**；**B-04-BUG知识库.md 为反哺源**（修复 Bug 后反哺本文件）。
> 技术栈: C# 10 / .NET Framework 4.7.2 / RimWorld 1.6 / HugsLib / Harmony / Unity

## 一、命名规范

| 元素 | 约定 | 示例 |
|---|---|---|
| 类/接口/方法/属性/事件/枚举成员 | PascalCase | `DevelopableAbility_Magic` |
| 接口 | `I` 前缀 | `IAscendReward` |
| 泛型参数 | `T` 前缀 | `TResult` |
| 私有/内部字段 | `_camelCase` | `_proficiency` |
| 参数 / 局部变量 | camelCase | `statPart` |
| 常量（含 private/internal） | PascalCase | `PlantWorkPerProf` |
| 枚举 | 名词单数（非 flags）；布尔用 `Is/Has/Can` 前缀 | `RewardRarity` |

- 用原语别名声明（`int/float/string/bool`），.NET 类型名仅用于静态成员访问。
- 禁止匈牙利命名、禁止缩写（`Id/Xml/Ftp` 等惯用缩写除外）。
- Mod 框架类命名带统一前缀便于检索：`Patch_*`、`Spell_*`、`Skill_*`、`DevelopableAbility_*`、`Mote_*`、`UI_*`、`StatPart_*`、`QuestNode_*`、`JobDriver_*`、`GameComponent_*`。

## 二、目录结构规范

```
Familia_Myth/
├── About/          # 模组元数据
├── Assemblies/     # 编译输出（只含本模组 DLL + 必需第三方 DLL）
├── Source/         # C# 源码（按职责前缀命名文件）
├── Defs/           # XML 定义（Hediff/Spell/Skill/Thing/Quest/Ritual/…）
├── Patches/        # PatchOperation XML（StatPart 注入、条件补丁）
├── Languages/      # 中英双语本地化（DefInjected + Keyed）
├── Textures/       # 贴图（Aseprite 源 + 导出 PNG）
├── Materials/      # 自定义 shader
└── AssetBundles/   # 资源包
```

- 新功能按「核心类 + 对应 Defs + 对应 Patches + 对应本地化」四件套落位，改动集中。
- `Data/`（原版/DLC XML）与 `decompiledFiles/` 为只读参考，绝不修改。

## 三、错误处理规范

- 只校验系统边界（玩家输入、原版回调、DLC 缺失）；内部代码信任框架保证。
- 异常处理原则：**不空吞**。catch 至少 `Log.Error(msg)`，能恢复则恢复，否则让问题显形。
- Harmony 补丁方法体一律 try-catch，防止单个补丁异常拖垮游戏主线程。
- 返回失败状态时，调用方必须处理失败分支（不静默忽略）。
- 原版 API 可能抛异常的位置（如 `Find.CurrentMap` 为 null）先判空再访问。

## 四、日志规范

- 用 `Log.Message`（信息）、`Log.Warning`（警告）、`Log.Error`（错误），禁止 `Console.WriteLine` 或裸 print。
- 错误日志包含定位信息：触发对象、当前阶段（如 `[Pharna] PawnName 升华失败: ...`）。
- 高频路径（每 tick / 每帧）禁止打日志，避免刷屏。
- 调试用 `DebugSettings`/`Prefs.DevMode` 保护，随功能完成移除。
- 游戏日志统一从根目录 `Player.log` 排查，与模组前缀关键词配合搜索。

## 五、安全规范

- DLC / 其它 Mod 依赖用 `PatchOperationFindMod` / `PatchOperationConditional`（NoMatch 分支）在 XML 层保护，或 `ModsConfig.XxxActive` 在代码层保护（如海之眷顾需 Odyssey）。
- 不提交任何密钥/Token/隐私数据；`Data/`、`lib/`、`Assemblies/` 第三方 DLL、`obj/` 不入库（.gitignore 已覆盖）。
- 不从网上下载执行不明 DLL；引入依赖前确认其来源与版本。
- 资源（Material/RenderTexture/Camera/GameObject）使用后必须释放，避免显存/内存泄漏。

## 六、性能规范

- 帧循环（`DrawAt`/`Tick` 高频路径）避免：LINQ 高频调用、闭包分配、`new` 临时对象、字符串拼接。
- 每 tick 逻辑优先改为每帧/间隔 tick（如 `find.TickManager.TicksGame % N`）。
- 魔法律/魔法弹运动计算保持纯函数，输入确定输出确定，便于复用与测试。
- 大量对象遍历前先缩小范围（map 内 cells / 列表过滤），避免全局 `PawnsFinder` 全量扫描。
- 咏唱词等文本渲染使用相机烘焙为贴图后缓存复用，不在每帧重建。

## 七、技术栈特定规范（C# / RimWorld / Harmony / XML）

### C#（net472 / C# 10）
```
✅ 类型明显时用 var；只读字段用 readonly；常量数字集中为 const
✅ 字符串插值 $""；null 判断 is null / is not null
✅ 集合过滤/转换用 LINQ；简单遍历用 foreach（禁 foreach 中增删）
✅ 随机取样（`Rand.Range` 或索引取元素）前校验候选集合非空，可能为空时提供兜底数据——空集合取随机索引会越界，而 `Rand.Range(0, 0)` 本身不报错（见 B-04 BUG-026）
```

### RimWorld 对象模型
```
✅ 逻辑放进正确的生命周期：Def / Hediff / GameComponent / MapComponent / Mote / WorldObject
✅ 存档持久化数据走 ExposeData()；Def 数据不可在运行期改写
✅ 优先对接原版能力体系（Ability/Verb/Job/StatPart）而非另起炉灶
✅ 需跨存读档保持的运行时状态（如静态集合/运行时注册表）随所属对象 ExposeData 持久化，并在 Load 完成后(PostLoadInit)从可持久化数据重建；勿依赖不参与 Scribe 序列化的 static/非存档字段
✅ AcceptanceReport：返回字符串(含空串)即「不接受/禁用」；表示接受用 return true
✅ 手动改变 Pawn/Thing 位置后必须同步 pather：`pawn.Notify_Teleported(endCurrentJob:false, resetTweenedPos:false)` 或 `pather.ResetToCurrentPosition()`，避免残留 nextCell 使下次寻路闪回原点（resetTweenedPos:false 保留平滑动画）
✅ 原版无位移型击退 API：自写逐 tick 位移（速度积分 + 每 tick 写回 Position）并用 `StunFor`（FullBodyBusy→PatherTick 短路）禁用寻路；徒手 verb 用 `pawn.verbTracker.AllVerbs`（天然排除装备武器），装备锐器用 `pawn.equipment.AllEquipmentVerbs`
✅ Def 派生型「生成器 / 工厂」实例（如 `GuildQuestGenerator`）必须绑定所属 Def：外部构造统一走静态工厂 `Create(def)`，勿各自 `Activator.CreateInstance` 后漏赋 `def`——派生属性（Category/Type/Label 等）会静默变 null，轻则丢奖励、重则 NRE（见 B-04 BUG-017）
✅ 对外入口（Debug 指令、事件回调、跨系统调用）先校验关键依赖（null → Log.Error + return），且校验必须排在**任何副作用**（Spawn / 注册 / 生成任务 / 发放）之前，避免"做了一半才发现参数不合法"的残留状态
✅ 复用原版部件/工具前先反编译核对其**隐式前置条件**：缺数据不在部件入口报错，往往在更晚的文本解析/结算期才炸（见 B-04 BUG-018 延迟回报部件缺 rewardGiver）→ 必要时自建预检部件或兜底分支
✅ 跨系统「归位/移交」必须与其**信号窗口**对齐：`SentSatisfied/SentUnsatisfied` 当拍成员仍在穿梭机容器内，归位须在此当拍完成（见 B-04 BUG-018）
✅ 从公共名单派生「待处理子集」（离场/结算/奖励名单）时**逐项列出应排除类别**，并分别核对成功线与失败线的口径差异（见 B-04 BUG-019：成功线须留已转正者、失败线不分组队）
```

### RimWorld IMGUI 界面（UI）
```
✅ 色值一律取自 `UI_Palette`（含稀有度四色与伟业九档色表），界面代码不写裸色值；分区描边用较淡的 `SectionBorder`，`Accent` 留给升华门槛刻度 / 评级文本 / 可升级提示
✅ GUI 全局状态用 `UI_Scope` 成对包裹（`Text` / `Color` / `Group`）：异常路径也会还原，替代手写 prev* 存取样板
✅ 工具提示统一用延迟求值重载 `TooltipHandler.TipRegion(Rect, Func<string>, int)`——原版只有 `(Rect, TipSignal)` 与 `(Rect, Func<string>, int)` 两个重载，**没有** `(Rect, string)`；id 用 `Gen.HashCombineInt(obj.GetHashCode(), 常量)` 保证稳定
✅ 界面文本经 `UI_Text.Width/Truncate` 度量与截断，避免长名被 `GUI.BeginGroup` 硬裁；文本键内不写格式说明符（见 B-04 BUG-024）
✅ 卡片像素常量集中在 `UI_GroupBox`（`TitleHeight` / `TitleIndent` / `TitlePaddingX` / `TitleLineOffset` / `SectionBorderThickness` / `BasicMargin`）：分区卡走 `DrawOutlinedCardBg`（标签框式标题、填充与边框同域），条目卡不描边、只靠底色 + 左侧色条区分
✅ 新窗口继承 `Window_FamiliaBase`（内容区模板 + `FitInitialSize` 尺寸换算 + 文本状态保护）；不保留顶部标题带的窗口把 `HasHeaderArea` 置 false
✅ 自绘进度条用 `UI_Bar`（底槽 + 按色静态缓存的纯色填充纹理 + 可选门槛刻度），不在帧循环里新建材质 / 纹理
✅ 动效只在该 `EventType.Repaint` 时绘制，相位取 `Time.realtimeSinceStartup`，不做状态累积、不改布局、不影响点击命中（如可升级呼吸）
❌ 每帧新建 `Texture2D` / `Material`，或手写逐像素纹理生成（GC 与上传开销；家族页雷达图为**已知例外**，见 `plans/UI视觉风格改版计划.md`）
❌ 复用原版私有实现细节（私有字段 / 非法枚举哨兵值）而不做可用性预检与降级（见 B-04 BUG-027）
```

### Harmony
```
✅ [HarmonyPatch(typeof(X), nameof(X.Member))] + 类内 static 方法 + [HarmonyPrefix]/[HarmonyPostfix]
✅ 重载方法写明参数类型数组；Prefix 返回 false 跳过原方法；Postfix 用 ref __result 改返回值
✅ 补丁体 try-catch；改动原版前先反编译确认原签名
✅ 补丁类一律 Patch_* 前缀并与文件名对应（单类文件类名=文件名，多类文件用「文件名前缀+语义后缀」），命名空间统一 FamiliaMyth.Patch（细则见 C-03）
✅ 错误日志统一 Log.Error($"[FamiliaMyth] {nameof(补丁类)} error: {ex}")，用 nameof 保证重命名后不脱钩
✅ Prefix 的 catch 必须 return true 放行原版逻辑——返回 false 会静默屏蔽原版方法，是本栈最危险的写法
✅ Prefix/Postfix 成对用 __state 时，Prefix 出错须写入让 Postfix 短路的哨兵值（IntVec3.Invalid / -1 / float.MaxValue），Postfix 首行校验后跳过
```

### XML（Defs / Patches）
```
✅ 引用类名带命名空间前缀（如 <li Class="Verse.HediffDef">）——xml 中类名注意命名空间前缀
✅ defName 全局唯一；ParentName 继承核对父子字段
✅ 条件补丁用 PatchOperationConditional / PatchOperationFindMod（含 NoMatch 分支）
✅ Hediff 的 initialSeverity > 0（避免被默认逻辑立即移除）
```

### 玩家可见文本（描述与叙事）

```
✅ `description` 只写**客观定性**描述（"大量 / 数次 / 大范围 / 短暂 / 一定距离 / 片刻"），不写精确数字与公式
✅ 精确数值下沉到图鉴；运行时精确值由 UI 承担（技能按钮充能数、`HediffComp_SkillState` 状态标签、`HediffComp_DisappearsWithCounter` 剩余次数）
✅ 各美德的 beginLetter / 心声等叙事文本保持「精神连结、自我振作」口吻，**不出现神力显现**
❌ 在 `description` 里写 `200%` / `5 格` / `3 小时` / `+200 × t + 100`（违反 `技能.txt`「非必要不出现具体数字」准则）
❌ 让自身 Buff 与范围光环**共用同一条 ThoughtDef**（叙事视角会错位，见 B-04 BUG-022）
```

### 本地化文本（Keyed / DefInjected）

```
✅ 四条文本路径各归其位（细则与取证见 C-03）：Def 字段→DefInjected；rulesStrings→DefInjected 整表；
   任务节点 SlateRef→`TKey` + `<DefName>.<引用名>.slateRef`；代码内文本→Keyed + `"Key".Translate()`
✅ `"Key".Translate(args)` 的参数占位符**只写裸 `{0}` `{1}`**；需要百分比/小数位时，在参数侧先格式化
   （`value.ToStringPercent()` / `value.ToString("F1")`）再传入
✅ Def 内文本一律保留作默认/兜底，由语言文件覆盖；改文本后跑根目录 `12-本地化检查.ps1` 确认七项
❌ 在语言文件里写 `{0:P0}` / `{0:F1}` 等 .NET 格式说明符 —— `Translate(...)` 走的是 RimWorld 的
   `GrammarResolverSimple`，`:` 会被当作 `{func:args}` 函数语法，未知函数**静默返回空串**
   （无红字、脚本也不报），表现为该参数位置显示为空（见 B-04 BUG-024）
❌ 把 Keyed 键填进 Def 字段（不会触发翻译，只会原样显示键名，见 B-04 BUG-021）
```

## 八、AI 高频错误防犯清单

> 基于本模组实际踩坑记录整理，详见 AGENTS.md「八」对应表。新增坑位时补充出现次数。

| # | 易错点 | ✅ 正确做法 | 次数 |
|---|---|---|---|
| 1 | 凭记忆写原版 API（如 `SetDuration`） | 先反编译核对，不存在的成员直接用字段赋值 | 1 |
| 2 | Harmony 补丁非 static / 签名错 | static + 参数类型数组 | — |
| 3 | 补丁无 try-catch | 包裹 try-catch + Log.Error | — |
| 4 | Mote/纹理/相机资源泄漏 | try/finally 销毁；DrawAt 中重查占位贴图 | 1 |
| 5 | 随机抽取死循环 | 权重耗尽判断 `tt > 0` | 1 |
| 6 | foreach 中增删集合 | 快照 / 反向遍历 | — |
| 7 | Hediff severity=0 被立即移除 | `initialSeverity` 置正 | 1 |
| 8 | XML 类名缺命名空间前缀 / defName 冲突 | 带前缀、全局唯一 | 1 |
| 9 | 魔法数字无出处 | 抽 const 并对齐设计文档 | — |
| 10 | Patch 中访问未初始化 Find 单例 | 判空 + 阶段判断 | — |
| 11 | 复用原版部件未核对其隐式前置（缺数据在解析/结算期才炸） | 先反编译确认前置；必要时自建预检/兜底 | 1 |
| 12 | 归位/移交与信号窗口错位（`Sent*` 当拍成员仍在容器内） | 在信号当拍完成归位 | 1 |
| 13 | 派生名单漏列应排除类别（把该留下的对象赶走） | 逐项列出排除集合并核对成败线口径 | 1 |
| 14 | 补丁 catch 里 `return false` 静默屏蔽原版方法 / 成对 `__state` 未设哨兵值 | Prefix 的 catch 一律 `return true` 放行原版；Prefix 出错时给 `__state` 写哨兵值令 Postfix 短路 | — |
