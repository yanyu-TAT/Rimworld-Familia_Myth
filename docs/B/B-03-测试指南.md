# 测试指南

> 项目测试策略与规范。本模组以**游戏内验证**为主（RimWorld mod 无独立运行环境，程序集依赖 Steam 本地游戏 DLL），辅以静态校验与反编译核对。测试随项目成长逐步完善，不接受一次性全覆盖。
> 技术栈: C# 10 双目标（net472 → 1.6 / net10.0 → 1.7） / RimWorld 1.6 + 1.7 / Harmony

## 一、测试分层

| 层级 | 范围 | 方式 | 何时执行 |
|---|---|---|---|
| XML 静态校验 | Defs / Patches 合法性 | PowerShell `[xml]` 解析 + defName 唯一性检查 | 提交前 / 新增 Def 后 |
| 本地化校验 | 中英文本对称性、Keyed/DefInjected 覆盖、XML 类型引用可解析性 | `pwsh -File .\12-本地化检查.ps1`（7 项） | 改动语言文件 / 重命名类名 / 提交前 |
| 反编译核对 | 原版 API 签名、字段、回调时机 | ilspycmd → kb/L0-证据/decompiled/1.6/ | 编写补丁/魔法/技能前 |
| 编译验证 | 两个目标框架均可编译、无新增警告 | `dotnet build`（默认双版本，`-f net472` / `-f net10.0` 单编） | 每次改动后 |
| 游戏内加载 | 无红字、Def 正常加载 | 启动游戏 + 查看 Player.log | 每次改动后 |
| 游戏内功能 | 核心玩法路径 | 开发者模式手测（DebugAction / 触发器） | 新系统完成时 |
| 咏唱词纹理 | 每条咏唱词都有对应离线 PNG | 调试指令「导出咏唱词纹理」后查日志（成功 / 失败计数）与 `Textures/Familia_Myth/Incantation/` | 新增 / 修改咏唱词后 |

## 二、编写时机（按项目阶段）

| 阶段 | 测试重点 | 不做的 |
|---|---|---|
| 框架/原型 | 编译 + 加载无红字 | 深度数值测试 |
| 核心功能稳定 | 游戏内功能路径逐条验证（恩惠→成长→升华→奖励→公会） | 边缘数值 |
| 数值调整 | 按能力值/魔法/技能设计文档核对实际效果上限 | — |
| 发版前（1.0.0） | 全量回归 + 兼容性（含 DLC 未启用场景）+ 本地化核对 | — |

## 三、验证规范

**命令**：
```powershell
dotnet build Familia_Myth/Familia_Myth.csproj     # 编译
powershell -Command "[xml](Get-Content <xml文件>)" # XML 解析校验
pwsh -File .\12-本地化检查.ps1                    # 本地化 7 项体检（含 XML 类型引用可解析性）
```

**游戏内验证要点**：
```
✅ 开发者模式开启后使用 DebugAction_Pharna / DebugAction_Quest / DebugAction_Misc 快速构造场景
✅ 新增魔法：咏唱 → 咏唱词显示 → 魔法阵 → 释放全链路；咏唱中断/目标死亡/重复释放
✅ 新增发展能力：特性出现、Stat 面板加成、熟练度增长与上限
✅ 武器同调：近战命中率信息卡倍率；装备近战武器每 1250 tick +1 且上限 = 发展能力熟练度；展示 Hediff 仅当前装备一条（换武器重建、空手/远程移除）且 label 档位 / tooltip 概率正确；每次挥击重置冷却、近战命中暴击 ×2 与淡红飘字；存读档保留武器熟练度；恩惠丢失后展示条随 Hediff_Pharna 移除
✅ 连攻：持续近战出手约 10 秒后力量/灵巧补正上升、停止攻击 10 秒归零；攻速 2.5 次/秒且熟练度 500 时各 +500、熟练度 999 仍封顶；远程/施法不计入；空手/拆墙计入；存读档后窗口清空但熟练度保留
✅ 精愈：有灵能链接（或「有魔法无 psylink」被 patch 视为有灵能）时精神力持续回升，越满越慢、满时停止；500 熟练度约转化消耗的 50%、999 约 99.9%；开启自动转化/施放灵能后按每 1% +0.005 涨熟练度，自然下降与冥想不回喂；纯精愈（无魔法/无 psylink）不生效；存读档熟练度保留
✅ 新增技能：主动施放/被动生效/触发条件、冷却、体力(精神力)消耗
✅ 公会：使者到访 → 日常对话接取（指定接取者）；强制使者出场即自动接取（不可拒绝）→ 完成 → 升级点数到账（**伟业不随任务发放**，由战斗结算单独记录）→ 评级晋升；强制任务失败/超时 → 3~5 天冷却后自动重发；等待重发期间该分类不出现日常使者
✅ DLC 未启用场景：涉及 Royalty/Ideology/Odyssey 的功能不应报红字
✅ 本地化：切换英文语种后，恩惠/技能/魔法/发展能力/任务信件/美德均正常显示（**不得出现原始 key 名**）；任务名与描述非空（TKey / slateRef 机制生效）
✅ 类名/文件名重命名后：`12-本地化检查.ps1` 第 [7] 项应仍为全绿（防 BUG-020 类加载红字）
✅ 神名：在文化界面右键神灵改名后，赋予恩惠信件与美德祷告飘字应显示该主神名；未选该结构文化 / 文化无神灵时应回落为「神明大人」（眷族口吻）／「你」（玩家视角）
✅ 美德心声飘字：触发美德当拍头顶应飘出独白或祷告之一；**中英环境均不得显示原始 key**，祷告句**不得显示 `{god}` 字面量**（该组键名由代码动态拼接、脚本抓不到，须人工核对中英对称）
✅ 美德触发链：崩溃被拦截当拍应进入美德（而非"既不崩溃也无美德"，防 BUG-023）；美德结束后 9~10 天内不再触发
✅ 魔力系统：属性面板显示「魔力储量 / 魔力转化效率 / 魔力转化速度 / 魔力操控」；**受伤导致意识下降时魔力操控与魔力转化速度同步下降**（`capacityFactors` 生效；转化速度的解释行应拆解为「效率 × 意识 × 基础转化量」，且三个数值**均不得为空**，防 BUG-024）；魔力池 gizmo 显示「当前 / 上限」并可开关自动转化；关闭后魔力停止增长而 psyfocus 保留；存读档后池值与开关状态不丢
✅ 魔力消耗：魔力不足时魔法按钮拒绝施法并提示「魔力不足」（不得出现原始 key）；爆裂魔法（消耗 2500）在池满值前无法施放；「重生女神之礼赞」自动治愈按魔力扣费、不足时自动关闭
✅ 数值平衡：专精单项到 500 约 9~20 天（应与 15~30 天的升级周期匹配）；平均培养 6 项应明显落后（6~10 倍）；**不应出现「六项自然全满」**
✅ 调参入口：成长衰减 4 个 const 在 `Hediff_Pharna.cs` 顶部；效果系数在 `Patches/StatParts_Pharna.xml`（及 `Patches_RangedDodge.xml`）；疼痛系数常量 `Hediff_Pharna.PainFactorPerPoint`（0.9995，作用于曲线折算值 `s`）；伟业在 `FeatUtility.TierThresholds`（九档阈值）、`FeatContext`（三路径权重）、`FeatTraitJudgers`（性质阈值）；任务升级点数在各 `Defs/QuestScriptDefs/*.xml` 的 `upgradePoints` 与过程 part 的 `BaseUpgradePoints`
```

**回归检查**：改动核心基类（Spell/Skill/DevelopableAbility/Mote）后，抽查存量内容不受影响。

## 四、Bug 验证与记录

- 复现 Bug 后先确认最小复现路径，修复后跑对应路径回归。
- 修复完成后按 `B-04-BUG知识库.md` 模板记录，检查是否暴露规范缺失。

## 五、测试示例（按需参考，非强制创建）

RimWorld mod 的"单元测试"通常成本高且价值有限，优先通过反编译核对 + 游戏内验证覆盖。以下场景值得考虑抽象纯逻辑函数（便于人工/脚本验证）：
- 能力值成长公式、意志触发概率公式、美德随机选择、魔法弹运动积分——这类纯函数输入输出确定，可抽离后单测或脚本核对数值。
