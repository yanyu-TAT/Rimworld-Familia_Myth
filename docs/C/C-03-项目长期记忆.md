## 运行时与构建运维约定

- **`Player.log`** **时效性**：日志文件由用户在本地运行时产生，**需要用户手动刷新才会更新**；未刷新时为旧版本运行日志，Agent 分析时须先向用户确认其时效，不能当作当前代码状态的证据。
- **`.shader`** **打包**：`Materials/` 下的 `.shader` 无法直接在游戏内生效，**需用户在 Unity 中手动打包为 AssetBundle**（`AssetBundles/`）才能生效。**修改** **`.shader`** **后必须提醒用户重新打包**，否则改动不会进入游戏。

## 命名与命名差异

- 框架类前缀约定：`Patch_*` `Spell_*` `Skill_*` `DevelopableAbility_*` `Mote_*` `UI_*` `StatPart_*` `QuestNode_*` `JobDriver_*` `GameComponent_*`。
- **Harmony 补丁命名与组织**：补丁类一律 `Patch_*` 前缀，且**以「相关功能/内容」命名**——
  - 技能/魔法/发展能力直接取其名：`Patch_TheWorld`、`Patch_Railgun`、`Patch_LuckOfTheSea`、`Patch_Ember_PreventDeath`、`Patch_Ember_Capacities`
  - 成长类用 `<能力值>Gain_<来源>`：`Patch_StrengthGain_Kill` / `_Down`、`Patch_EnduranceGain_Damage` / `_Heal` / `_Nutrition`、`Patch_DexterityGain_Craft`、`Patch_AgilityGain_Move` / `_Dodge`、`Patch_ManaGain_Entropy` / `_Psyfocus` / `_NeedsPsyfocus`、`Patch_SkillGrowth`、`Patch_WillGain_Meditate` / `_Inspiration` / `_Charity` / `_Interaction`
  - 系统类用系统名：`Patch_Virtue_Trigger`、`Patch_VirtueControllable_*`、`Patch_AbnormalResistance_*`、`Patch_GuildEnvoy_Talk`、`Patch_FamiliaTab_PreOpen` / `_Draw`
  - **不以被补丁的原版类型命名**（避免 `Patch_RecordsUtility_PawnKilled`、`Patch_Pawn_PathFollower` 这类与功能脱节的写法）
  - 单类文件的类名 = 文件名；一个文件可含多个补丁类（不强制一文件一类），此时统一用「文件名前缀 + 语义后缀」；命名空间统一 `FamiliaMyth.Patch`
  - 唯一例外：`HistoryTabHelper.cs` 内含 UI 工具类（属 `FamiliaMyth.UI`）与 2 个补丁类（写在同文件的 `FamiliaMyth.Patch` 块内），文件名取工具类名
- **Harmony 补丁目标写法**：优先 `[HarmonyPatch(typeof(X), nameof(X.Y))]`（编译期可校验）；**原版方法为 private/protected、或类型为 internal 时**只能用字符串形式（如 `Pawn_PathFollower.TryEnterNextPathCell` 为 private、`WorkGiver_FightFires` 类型为 internal），此时须格外注意拼写与原版版本变更。
- **补丁异常防护**：所有 `Prefix/Postfix` 方法体必须 `try-catch` + `Log.Error($"[FamiliaMyth] {nameof(补丁类)} error: {ex}")`；`Prefix` 的 catch 必须 `return true` 放行原版逻辑（返回 false 会静默屏蔽原版方法，是最危险的写法）；成对 `__state` 的 Prefix 出错时写入让 Postfix 短路的哨兵值（`IntVec3.Invalid` / `-1` / `float.MaxValue`），Postfix 首行校验并跳过。
- **本地化：四条文本路径（均有反编译 / 原版实证，勿混用）**：
  1. **Def 字段**（`label` / `description` / `letterText` 等）→ `DefInjected`，键名 `<DefName>.<字段路径>`；列表字段用索引（`roles.0.label`、`outcomeChances.1.label`、`stages.0.description`）
  2. **语法规则列表**（`questNameRules.rulesStrings` / `questDescriptionRules.rulesStrings`）→ `DefInjected` 整表替换：`<DefName>.questNameRules.rulesStrings` + `<li>`
  3. **任务脚本节点文本**（`SlateRef<string>` 字段，如 `QuestNode_Letter.label` / `QuestNode_ExploitsReward.letterLabel`）→ Def 元素加 `TKey="引用名"`，语言文件键 `<DefName>.<引用名>.slateRef`（反编译依据：`SlateRef<T>` 内 `[MustTranslate_SlateRef] private string slateRef;`）
  4. **代码内文本** → `Keyed` + `"Key".Translate()`，键名规范 `FamiliaMyth.<域>.<语义>`（域用 PascalCase 功能名，如 `FamiliaMyth.QuestLetter.Accept`）
- **Def 字段不会自动 Translate**（取证：`Verse/Def.cs` 的 `LabelCap => label.CapitalizeFirst()`、`TaggedString(string)` 仅赋值、`Verse.AI/MentalState.cs` 的 `GetBeginLetterText()` 均不 Translate；`LoadedLanguage` 的 `Keyed` 与 `DefInjected` 是两套独立加载）。因此**切勿把 Keyed 键填进 Def 字段**——它不会被翻译，只会把该键原样显示在游戏里；原版 `Data/` 中 0 处此写法（本项目历史遗留 58 处已于本地化迁移中修复）。
- **Def 内文本一律保留**（作为默认文本与兜底），由 `DefInjected` / `TKey` 覆盖；**不要清空 Def 内文本**——语言键缺失时会退化成 defName。原版模式即：`<label TKey="Xxx">Default text</label>`。
- 本地化完整性检查脚本：根目录 `12-本地化检查.ps1`，共 7 项 —— ①Def 文本覆盖 ②任务 TKey→slateRef ③rulesStrings 规则列表 ④错误 key 占位 ⑤Keyed 中英差集 ⑥代码内 Translate 键覆盖 ⑦**XML 类型引用 → 源码类型可解析性**（类名重命名/笔误导致 `Could not find a type named ...` 的加载期红字，靠此项自动兜住；方法引用 `Type.Method` 视为合法）。
- **`"Key".Translate(...)` 的参数语法不是 `string.Format`**：它走 RimWorld 的 `GrammarResolverSimple`，`:` 会被当作 `{func:args}` 语法，因此 **`{0:F0}` 这类格式说明符不可用**——需要格式化时先在参数侧 `value.ToString("F0")`，再作为普通 `{0}` 传入。无参 `.Translate()` 直接查表返回原文（不做符号解析），所以文本里含 `{BASETEXT}` 等二次占位符是安全的，但**这类 key 今后不可带参数调用**（否则触发 `Could not resolve symbol` 的 Log.ErrorOnce）。
- **`FamiliaMythMod.godName`（默认 `"你"`）是预留给玩家自定义神明名称的接口，不参与本地化**：不要把它改成 `Translate()` 调用，也不要为它新建 Keyed 键。它以 `{god}` 参数注入仪式文本（`RitualOutcomeEffectWorker_GrantPharna`），将来由玩家设置面板赋值。
- **数值平衡框架**：
  - **成长双衰减**：`实际增量 = 基础增量 ÷ (1 + 单项超量/500) ÷ (1 + 总量超量/2500)`；单项超量 = `max(0, 该项当前值 − 400)`、总量超量 = `max(0, 六项当前值之和 − 2000)`；**未超阈值时保持正常线性增长**
  - `Hediff_Pharna.CycleExp` = 六项 current 之和，即「本周期累积经验」——`Ascend()` 清零 current 时天然归零，**无需新增字段与 Scribe**
  - 参数集中在 `Hediff_Pharna.cs` 顶部 4 个 const：`StatDecayThreshold(400)` / `StatDecayScale(500)` / `CycleExpDecayThreshold(2000)` / `CycleExpDecayScale(2500)`
  - **设计意图**：该阈值组合使「专精 1~2 项」几乎不触发总量衰减（专精 1 项时 cycleExp 最高仅 999 < 2000），而「平均 6 项」在每项 333 时就触发 → 数学上逼出「只养 2~3 项」的养成取向
  - **k 的构成与上限**：`k = current + potential`；current 每级上限 999（`maxStatus`）、等级上限 Lv10（`HediffDef.maxSeverity`——原版 `Hediff_Level.ChangeLevel` 即用 `def.maxSeverity` 夹取）→ **k 天然封顶 9990**
  - **效果系数锚点**：`k ≈ 4000`（Lv5 实际水平）≈ 原版精锐（动力甲 + 传奇武器 + 技能 20）的 1.2~1.5 倍；`k = 9990`（Lv10 理论满）不设强度上限，靠养成难度限制可达性
  - **伟业值固定量**：`QuestUtilities.DailyExploits = 500` / `RankUpExploits = 900`，**不随难度点数变化**；`CalculateTaskParams` 的 `points`（原版点数 × `PharnaGrowthFactor`）**仅用于标定任务难度**，仍保留
- **批量修改 XML 数值的安全做法**：先备份目标文件 → 用「按块替换」（`[regex]::Replace` + MatchEvaluator，以 `Match.Index` 为基准）而非「绝对索引拼接」——后者会把数值插进标签中间、造成 XML 损坏 → 改完必须 `[xml]` 解析校验，失败立即从备份回滚。

## 约束与约定（沉淀自项目记忆）

- Mote\_Incantation 必须保存原始文本，DrawAt 中 tex 为 Placeholder/null 时重查 GetTexture。
- Vanish() 记录 forcedProgress，防止强制结束进度回滚。
- BuildTexture 用 try/finally 销毁临时 Material/RenderTexture/Camera/TextMesh。
- 咏唱词世界尺寸用 MeshRenderer.bounds 计算，displayH=2.5f，linearScale 复位 (1,1,1)。
- 大剑贴图 drawSize (6.01, 6.01)，保证剑尖世界长度与攻击范围 2.5 匹配。
- 近战触类魔法用 `Verb_CastAbilityTouch` + `CastAbilityOnThingMelee`，stunTargetWhileCasting=true，range=-1。
- 升华奖励随机选择需 `tt > 0`。
- 技能状态类 Hediff 的 `initialSeverity` > 0。
- `HediffComp_Disappears` 直接设 `ticksToDisappear`（无 `SetDuration` 方法）。
- 技能充能/冷却/active 为运行时状态，Skill.ExposeData 已持久化 charge/cooldownTimer/active；跨存档运行时集合在 ExposeData PostLoadInit 重建。
- 存读档不触发 HediffComp.CompPostPostAdd/CompPostPostRemoved（Hediff 经 ExposeData 恢复而非 AddDirect）；跨存档运行时集合须在 Load 后重建。
- HediffCompProperties 的 compClass 可在 XML 用 <compClass> 覆盖构造函数默认值（如 EmberInEffect 挂带 skillDef 的 props 后指定专属 comp）。
- AcceptanceReport：任何字符串（含空串）构造的 report 均 accepted=false（返回字符串=拒绝）；表示接受须 return true（bool→WasAccepted）。
- 原版充能按钮机制：Command_Ability.TopRightLabel => Ability.GizmoExtraLabel => charges/maxCharges，由 Command 基类于按钮右上角绘制(GrayTextBG)。
- 技能/魔法数值时间换算（以技能.txt 的游戏内时间为准）：游戏内 1 日 = 60000 tick，1 游戏小时 = 2500 tick；SkillDef.cooldown 填现实秒 = 游戏内时长换算成 tick 后 /60（cooldown x 60 = 游戏内 tick）。例：夹枪冲锋/居合 2小时 -> 5000 tick -> cooldown约83；回旋踢 3小时 -> 7500 tick -> cooldown=125。
- 直线路径索敌/贯穿统一走 `RangeUtilities`（WeaponHelper.cs 内）：GetHitCellsAroundStraightWay（沿线地格采样）、GetEnemiesAroundStraightWay（沿线敌对索敌）、GetDest(start,end,map[,validator])（射线逐格推进，validator 返回 false 的格停下且不纳入 endCell）。居合/夹枪冲锋/超电磁炮共用。
- 查询"pawn 自身正处于生效状态的指定技能"用 `PharnaUtility.GetActiveSkill<T>(this Pawn)`（遍历 skills 取第一个 s is T 且 active）。区别于嘲讽 `Provokers` 静态集合（Patch 需遍历敌周围多个嘲讽者取最近）——两者语义不同，勿互相替换。
- 原版 `VerbUtility.GetDamageDef(this Verb)`：对 `LaunchesProjectile` 的 verb 返回 `GetProjectile()?.projectile.damageDef`（子弹的伤害 Def），否则返回 `verbProps.meleeDamageDef`；故远程/近战均可直接用 verb.GetDamageDef()，勿误以为远程为 null。
- `Verb.CurrentTarget`（protected currentTarget 的公开属性）可读，Harmony 前缀里可直接 `__instance.CurrentTarget` 取本次开火目标。
- 效果按"剩余次数"而非固定时长结束的强化技能（超电磁炮）：效果 Hediff 挂 SkillInEffect(驱动 active) + `HediffComp_DisappearsWithCounter`(维护剩余次数，CompShouldRemove 判 cnt<=0 归零自动移除 → 收尾 active=false → 开始冷却)。
- 强化普攻技能用 Harmony Prefix 拦截 `Verb_LaunchProjectile.TryCastShot`，注入中先即时贯穿结算再 `return false` 屏蔽原弹——屏蔽原弹避免原单发伤害与贯穿叠加成双伤。
- 原版 `Verse.Mote` 的 exactPosition/exactRotation/linearScale/instanceColor 均为 public；用通用 Mote + Graphic_Mote 即可做"沿直线拉伸 + 旋转"的一次性光带，无需自定义子类（超电磁炮 Mote_RailgunImpact 即如此）。同款贴图惯例：Slash.png / LineSolid.png 均为 64×16 水平长条。
- 技能状态指示不再需要自定义 Hediff 子类：Def 用 `HediffWithComps`，让 HediffComp override `CompLabelInBracketsExtra`，由 HediffWithComps.LabelInBrackets 自动遍历拼接（原自定义 Hediff_SkillState 已删除）。
- 居合等"释放后短时延迟执行"的技能：用基类 `Skill.active` 表达"正在生效"（替代曾自定义的 isSneathing），ExposeData 已由基类持久化 active。
- 任务过程 part 的 tick 语义：`Quest.QuestTick` **只对 `State == Enabled` 的 `QuestPartActivable`** 调用 `QuestPartTick`，而 `inSignalEnable` 缺省则永不启用 → "任务一开始就要跑"的 part 用 `QuestGen.quest.InitiateSignal`（`QuestManager.Add` 中 part 全部添加完才 `quest.Initiate()`，时机安全）。
- `QuestGenUtility.HardcodedSignalWithQuestID` **幂等**：对已形如 `Quest{id}.xxx` 的串原样返回；`QuestNode_Signal` 会把 `<inSignal>` 自动转成同串，嵌套节点内层再转也安全。
- `WorldObject.ExposeData` 在读档时经 `InitializeComps()` **从 `def.comps` 重建** comp 列表（非从存档反序列化）→ 后期用 Patch 往 `WorldObjectDef.comps` 注入的自定义 comp **对已有存档同样生效**（状态由各自 `PostExposeData` 持久化）。
- `WorldObjectComp.GetCaravanGizmos(Caravan)` 由 `Caravan.GetGizmos` 对**该 tile 上的世界对象**逐个调用 → "世界层停留式交互按钮"（如定居点领取/交付）就挂在这里；`Settlement` 不可改，交互能力只能经 comp 提供，而 `WorldObject` 无实例级 AddComp API，故 comp 必须声明在 **def 级 comps**（原版 `TradeRequestComp` 同款）。
- 「Def 派生型生成器」必须经统一工厂 `GuildQuestGenerator.Create(def)` 构造（绑定 def）；漏绑会使 `Category/Type/LetterText` 静默为 null（丢升级点 / NRE），详见 B-04 BUG-017。
- 远行队伏击用原版 `IncidentDef "Ambush"`（`Caravan` 目标自动生成临时伏击图，`blockExitGridUntilBattleIsWon=true` 打赢才能离图）；`parms.forced=true` 会**短路 `CanFireNow` 的全部检查**，故必须自行调用 `CaravanIncidentUtility.CanFireIncidentWhichWantsToGenerateMapAt(caravan.Tile)`——该 tile 被未开 `allowCaravanIncidentsWhichGenerateMap` 的世界对象（定居点/站点）占用时无法生成伏击图，须跳过并在下一轮重试。袭击者派系被 `GeneratePawns` 内部覆盖，无法指定。
- `ThingDef.tradeability` **默认 `Tradeability.All`**（`ThingDef.cs` L324）；块堆 `<tradeability>None</tradeability>` 且 `category=Item`、无 `building` → 只靠"可卖性"过滤即可排除块堆，建筑则靠 `def.building != null`。
- 生成期装配原版部件必须**显式传 inSignal**（如 `quest.PawnsArrive(..., inSignal: quest.InitiateSignal)`）：`PawnsArrive/SetAllApparelLocked/Letter/AddMemoryThought/PawnJoinOffer` 等扩展的缺省取值是 `slate["inSignal"]`，而根层 slate 没有该变量（`Slate.Get` 静默返回 default 不报错）→ 部件永不触发。
- `QuestPart_ExtraFaction` 的 `inSignalRemovePawn(s)` 在原版是**死代码**（所有调用点均未设 `inSignalEnable`，而 Activable 只在 Enabled 时才处理信号）；要真正移除成员标记必须显式设 `inSignalEnable`（本项目用任务接取信号）。
- 穿梭机 `CompShuttle.requiredPawns` 是公开列表、可运行时增删，用于实现「动态登机名单」（起飞达标 `AllRequiredThingsLoaded` 逐名检查容器，名单为空即视为满足）；`Util_TransportShip_Pickup` 的船与 job 全挂在 util 内层信号上，且该 util **不含任何 Letter 节点** → 不发外层信号船永不降落、抵达信须自行监听 `pickupShipThing.Spawned`。
- 任务内发动地图袭击用 `IncidentDefOf.RaidEnemy.Worker.TryExecute(new IncidentParms{ target=Map, points, faction, forced=true, quest })`：该路径**不经过 `CanFireNow`**（「允许大威胁」等难度开关必须自判），且实机强度会在传入点数上**再乘**到达方式/策略的点数曲线。
- 复用原版「延迟回报」部件（`QuestPart_AddQuestRefugeeDelayedReward`）前必须确认 `lodgers` 中有「未死 + 非玩家派系 + 非囚犯」的候选，否则子任务会在文本解析期抛 `Grammar unresolvable`；本项目以 `QuestPart_AddQuestRefugeeDelayedRewardSafe` 覆写 `CanAdd` 预检（见 B-04 BUG-018）。
- 结算/离场/奖励等「派生名单」必须逐项排除应留下或已处理的对象类别（如离场名单须排除「已登机」与「已转正」者），且成功线与失败线的排除集合不同（见 B-04 BUG-019）。
- 失败结算里的「转中立后自行离场」统一走 `LeaveQuestPartUtility.MakePawnsLeave`（内部按 extra home → extra mini 归位 + `LordJob_ExitMapBest` 离图）；**已被玩家囚禁/奴役者须提前从名单剔除**，否则会被解除 guest 状态后赶出殖民地。
