# C-02 架构详解

> 关键系统架构与决策记录。新增系统或重大调整时更新。

## 一、总体分层

```
Defs/Patches(XML 定义与条件注入) ←→ Source(C# 逻辑) ←→ Languages(本地化)
        ↓                                  ↓
    原版能力体系(Ability/Verb/Job/StatPart/Hediff) + Harmony 补丁
        ↓
    Unity(IMGUI/TextMeshPro/CoreModule) + 自定义 Mote 特效
```

## 二、核心系统

### 恩惠（Hediff_Pharna）
- `Hediff_Level` 子类承载六维能力值 + 潜在值 + 经验/伟业值。
- 升级条件：任一项能力值 ≥ 500（D 级）且伟业值 999。
- 升华：潜在值保留、能力值清零、伟业值清零、等级 +1，并在仪式中发放升级奖励。
- **六维效果归属**（`Defs/StatDefs/PharnaStats.xml` + `Patches/StatParts_Pharna.xml`）：力量/耐久/灵巧/敏捷各自注入原版战斗与生产 Stat；**魔力只管「魔力储量上限（`ManaMax`）」与「魔力转化效率（`ManaConversion`）」**（另有信息卡展示项 `ManaConversionSpeed`「魔力转化速度」，为只读派生值、不参与实际结算）；**心灵熵阈值与冥想精神力获取归意志**；魔导发展能力提供心灵熵消散率与魔力操控。**魔力不再直接加成魔法强度**。

### 升级奖励（AscendHelper）
- `IAscendReward`（RewardType：发展能力/技能/魔法；RewardRarity：Common/Uncommon/Rare/Unique）。
- 从 `DefDatabase` 自动注册，按稀有度加权（20/10/1/0）不重复抽取，`tt > 0` 防死循环。

### 魔法（Spell : Ability）
- 复用原版灵能（Psyfocus/熵）与技能栏；`SpellDef` 定义咏唱词/魔法阵层/稀有度/分类/魔力消耗（`manaCost`）。
- **三层资源链**：精神力（原版 psyfocus）→ 经**转化效率与意识**折算为**魔力**（`Hediff_Pharna.manaPool`，上限 `ManaMax`）→ 咏唱时消耗魔力，由**魔力操控**决定魔法强度；两个过程都产生副产物**心灵熵**（原版 entropy）。
- 转化常态进行（每秒投 0.25% psyfocus），魔力池满则停；每秒产出 = `ManaConversionSpeed`（= 每 100% 精神力产出 `ManaConversionRate` × 每秒投入比例）；`Gizmo_ManaPool` 右上角角标可随时开关自动转化。
- 咏唱流程：verb 咏唱 → 逐行咏唱词（Mote_Incantation 相机烘焙）→ 魔法阵展开（Mote_MagicCircle）→ 释放。
- 魔力操控：基础 `ManaControl` + 按 SpellType 分类的 `ManaControl_Attack/Heal/...`，经 `StatPart_ManaControl` 过滤注入，`GetCurrentManaControl()` 统一取值。三要素来源 = **魔法种类**（分 Stat）× **魔导熟练度**（`ApplyManaControlModifier`）× **意识**（原版 `capacityFactors`）。
- 魔法弹：`BaseMagicMissileState` 纯运动学积分器（位置/速度/加速度/限幅），状态机切换多段轨迹。

### 技能（Skill）
- 主动/被动/触发三类；Skill 抽象基类 + SkillDef（maxCharge/cooldown/duration/checkInterval）。
- 充能机制：charge（当前可用次数，0..maxCharge 夹取）+ cooldownTimer（回充倒计时）替代单冷却闸。
  常态被动不跑冷却；充能未满且不在冷却时启动回充，冷却结束回一充；释放成功消耗一充。支持多段/击杀重置类技能。
- 效果生命周期：Skill.active 标志 + HediffComp_SkillInEffect（挂在效果 Hediff 上的 comp）。
  效果 Hediff 添加 → CompPostPostAdd → 技能 NotifyEffectStart(active=true)；移除 → NotifyEffectEnd(active=false)。
  active 期间 ShouldCooldown=false，不进入冷却/回充（供嘲讽、余烬等持续效果使用）。
  注意：存读档不触发 CompPostPostAdd/Removed（Hediff 经 ExposeData 恢复），跨存档的运行时集合需在 ExposeData 的 PostLoadInit 阶段重建（如嘲讽 Provokers）。
- 状态指示：Def 用 HediffWithComps，挂 HediffComp_SkillState（override CompLabelInBracketsExtra，由 skillDef 反查 pharna.skills 中技能实例，取 Skill.StateText 显示充能/冷却/可适用）。利用 HediffWithComps 自动遍历 comp 的 CompLabelInBracketsExtra 拼进括号标签，无需自定义 Hediff 子类。
- 路径索敌/贯穿工具：RangeUtilities（WeaponHelper.cs 内静态类）统一提供直线路径地格采样 GetHitCellsAroundStraightWay、沿线敌对索敌 GetEnemiesAroundStraightWay、带可选 validator 的射线终点推进 GetDest（遇实心墙/不可通行即停）。居合、夹枪冲锋、超电磁炮共用，取代各自重复的私有 GetHitCells/GetEnemiesOnPath。
- 泛型查询：PharnaUtility.GetActiveSkill(this Pawn) 返回 pawn 上第一个且 active=true 的指定技能实例，否则 null；居合吸收伤害补丁、嘲讽等据此判定。
- 按次数计数的强化型主动技能（超电磁炮）：效果 Hediff 挂 HediffComp_SkillInEffect（驱动 active）+ HediffComp_DisappearsWithCounter（维护剩余次数，归零 → CompShouldRemove 自动移除 → SkillInEffect 收尾 active=false → 开始冷却）；由 Harmony Patch 拦截原版 Verb_LaunchProjectile.TryCastShot，注入中改为即时贯穿结算（返回 false 屏蔽原弹，天然无双伤）。
- 不消耗精神力，但有使用条件与咏唱时间。

### 发展能力（DevelopableAbility）
- 熟练度体系：每 100 熟练度升一档，映射 I~SSS 12 档 Trait。
- `StatPart_DevelopableAbility` 运行时遍历恩惠上能力，按 StatDef 逐项 Factor 修正；系数为常量便于调参。

### 意志/美德
- 触发：精神崩溃前由 `Patch_Virtue_Trigger` 拦截（factor = 1.0）或受击时（`Notify_PawnPostApplyDamage`，factor = 0.1），概率 `0.75(1 − e^−0.00025·意志)`；五种美德（坚定/无畏/专注/勇猛/振奋）各有通用 + 附加效果，持续 1~2 天，结束后内置冷却 `(10 − 0.001x)` 天。
- **启动失败必须回退**：`TryTriggerVirtue` 先赋值 `currentVirtue` 再 `TryStartMentalState`（`PostStart` 依赖前者取类型），启动失败须置回 `null`——否则 `Patch_Virtue_Trigger` 会误判"已在美德中"而静默吞掉本次崩溃（见 B-04 BUG-023）。
- **美德心声飘字**：`PostStart` 末尾用 `MoteMaker.ThrowText` 随机飘出独白/祷告（机制与键位见 C-03 / C-06）；`type` 与 `buff`/`mote` 均参与 `ExposeData`，读档后仍能正确收尾。
- 通用效果（×150% 工作速率、×50% 休息下降、+50% 学习速率）五种皆有；范围效果经 `HediffCompProperties_GiveHediffsInRange` 授予周围友方（该组件排除拥有者自身，自身效果写在主 Buff 上）。

### 公会
- `GameComponent_FamiliaRankTracker`：存档级多分类评级状态（评级/升级点数/强制任务 id/失败重发冷却）；`GameComponentTick` 低频轮询（1000 tick）统一驱动发布——强制使者（达标自动派发 / 冷却到期重发）与日常事件（入队间隔 0~4 天，入队后再经事件队列 1~3 天延迟到访）共用"全局单槽使者"互斥门。
- **使者单槽**（`GameComponent_GuildEnvoyTracker.curEnvoy + curQuestGen`）：同一时刻至多一个在场待处理使者；`Register` 顶替旧使者、对话/按钮后 `RemoveEnvoy` 清槽。
- **接取形态分轨**：日常任务经使者对话接取（须指定有恩惠的接取者）；强制任务于使者出场时**自动接取**（`TrySpawnRankUpEnvoy` 内直接 `SummonQuest` + `OnRankUpQuestStart`），不可拒绝、不可拖延，使者仅承担宣告演出。
- **失败/超时自动重发**：超时分支 `QuestPart_RankUpFailed` → tracker 写入 3~5 天重发冷却（`rankUpQuestRetryTick`），轮询到期自动重新派使者；成功晋升 `OnRankUpRequestDone` 复位状态，杜绝"失败后评级升级永久卡死"。
- **公会派系运行时补建**：FactionDef 不产生世界实例（各 count=0），`EnsureGuildFaction` 在加载时惰性补建隐藏派系并保持与玩家中立，使者方有归属派系。
- **任务点数统一**（`QuestUtilities.CalculateTaskParams(bool isRankUp, out threatPoints, out totalExploits)`）：点数 = 原版基准站点威胁 × 全殖民地恩惠成长因子（bonus = 总等级×`LevelWeight(1/80)` + 总经验×`ExpWeight(1/20000)`，**无上限**）×（强制再 ×1.5，`RankUpMultiplier`）；点数直接填 `SitePartParams.threatPoints`（站点）或 `IncidentParms.points`（袭击）；伟业值 = **固定量**（日常 `DailyExploits(500)` / 强制 `RankUpExploits(900)`），不随点数变化，点数仅用于标定任务难度。
- **奖励名单化发放**（`QuestUtilities.DistributeExploits(List<Pawn> participants, Pawn acceptor, float totalExploits, string letterLabel, string letterHeader)`）：内部过滤存活且有恩惠者；acceptor 在名单且多人 → acceptor 50% + 名单其余均分，否则名单全员均分；发放成功返回 true 并发送结算信。
- **奖励部件**：由各任务自己的过程 part 承担（据点清剿为 `QuestPart_SiteClearanceReward`），**不设通用奖励 part**。其中 `snapshotSignal`（默认 `site.AllEnemiesDefeated`）到达时经 `QuestUtilities.SnapshotSiteParticipants` 快照站点在场的受恩惠玩家成员到 `participants`（只记一次；结算时若名单为空会兜底补快照）；`inSignal`（默认 `rewardsReady`）时按快照名单调 `DistributeExploits` 发伟业值，并就地调 `GainPoints` 发升级点数。
- UI_FamiliaPage 展示眷族评级、升级点数进度与成员卡；成员卡的头像列可点击，跳转并选中对应眷族后关闭主标签页（`CameraJumper.CanJump` → `TryJumpAndSelect` → `Find.MainTabsRoot.EscapeCurrentTab`，与服务原版历史页跳转同一顺序）。

### 任务子系统约定细节（Quest 三件套）
- **三件套范式**：每任务 = 根节点 `QuestNode_Root_{Daily/RankUp}_{任务名}`（生成期：统一点数/参数、准备任务专属对象、装配过程 part 与奖励部件；slate 键约定 `difficulty/totalExploits/sitePartsParams/siteFaction` + 任务专属如 `victims`）+ 过程 part（多阶段任务：`QuestPartActivable` 子类，Stage 枚举 + `QuestPartTick` 每 ~250 tick + 信号转接；线性任务可省略）+ 奖励部件（各任务自建，如 `SiteClearanceReward` 兼发伟业值与升级点数）+ 评级部件（`RankUpComplete` / `RankUpFailed`）。各任务自实现但规格相似。
- **quest 信号约定**：`site.AllEnemiesDefeated`（威胁清除=快照/入队/奖励触发点）、`site.MapGenerated`（进图放置）、任务自定义 `rescueDone`（停站点超时表）、`rescueEvacuate`（召唤穿梭机 util）；穿梭机 thing 信号 `pickupShipThing.Arrived / SentSatisfied / SentUnsatisfied`（原版 `ShipJob_Arrive` 广播 Arrived、`CompShuttle.SendLaunchedSignals` 广播 Sent*）；发放统一走 `rewardsReady`。所有 tag 在生成期经 `QuestGenUtility.HardcodedSignalWithQuestID` 固化为 `Quest{id}.*` 同串，运行时 `SendSignal` 直发同串即可被 Quest 接收。
- **「紧急救援」就地接送流程（样板）**：接取 → 站点（威胁 part=点数×0.5：`Manhunters` 兽群，或 `ModsConfig.AnomalyActive && Rand.Chance(0.5) && DistressCall_Fleshbeasts` 可用时切腐化营地整套；遇难者 N=Clamp(1+floor(points/1000),1,5)、随机中立/友好可见派系 worldPawn）→ `QuestPart_RescueSpawn`（`site.MapGenerated` 时于距中心 >20 格处放置，部分倒地不出血；站立者发守点 lord 防离图）→ 威胁清除（`site.AllEnemiesDefeated`）：
  1. `QuestPart_Rescue`（Enable 当拍）：快照参与者 + **幸存者难民式临时加入玩家派系**——当拍释放守点 lord（守点周期到加入为止，之后不再发放）后 `SetFaction(Faction.OfPlayer)`（真实加入 → 上头像栏/可指挥；任务全程由 `QuestPart_ExtraFaction(原派系, HomeFaction)` 声明受害者带「原派系」标记 → 角色卡显示原派系、lodger 默认不可入远行队、死亡/离图时原版行为自动归还原派系，无人口白送）+ 发 `rescueDone`（解除站点 2 天搜救超时表 `WorldObjectTimeout 120000/inSignalDisable=rescueDone`）+ 启动 **3~6 小时（7500~15000 tick）** 倒计时；
  2. 到点发 `rescueEvacuate` → XML util `Util_TransportShip_Pickup`（requiredPawns=$victims、owningFaction=$rescueFaction、登机窗口 `leaveDelayTicks=180000`(3 天)、满载即飞）就地降落；**仅遇难者可登机**（required 无条件放行，`acceptColonists=false` 关闭玩家殖民者搭便车通道）；
  3. `pickupShipThing.Arrived` → 「穿梭机已抵达」信件；登船窗口内玩家治疗/护送伤员登机；
  4. `SentSatisfied`/`SentUnsatisfied` → `Settle`：先 `RestoreOriginalFactions` 全体幸存者归还原派系——成功（满载起飞）按 `登船存活数/生成总数` 计算 ratio → `DistributeExploits(participants, acceptor, baseExploits×ratio, …)` + 升级点 +10，登机者随后由穿梭机带回原派系（引擎：contents 打包进离场特效带离）；失败（超时未满起飞）**穿梭机离开即任务结束**——已登机者随船返回，滞留者归还原派系后安排 `LordJob_ExitMapBest` 自行离场，其后离场/世界化由系统兜底。
  - 全灭（`Notify_PawnKilled` 过滤遇难者、存活 0）即时失败（不召穿梭机）；2 天未清威胁由站点超时失败。
- **「罪犯追捕」押解流程（样板）**：接取 → 站点（Outpost 守卫 `points×GuardFactor(0.8)` + 1 名同派系通缉犯 worldPawn，`QuestPart_CriminalHuntSpawn` 于 `site.MapGenerated` 放营地中心并守点迎战）→ 威胁清除（`site.AllEnemiesDefeated`；`Pawn.ThreatDisabled`：**倒地敌意者不算威胁** → 击倒活捉可行）：
  1. 当拍快照参与者 + 发 `huntCleared` 停站点超时表；通缉犯已死 → 普通结算（伟业值 ×1 + 升级点 +10，End Success）；
  2. 存活 → 引导玩家打包进远行队带离窝点（原版重组远行队可将倒地非玩家派系视为被拘捕囚犯；离图当拍兜底 `SetGuestStatus(玩家, Prisoner)`）→ 离图起 **1~3 天**计时（仅押解对象在玩家远行队/据点期间推进；**被玩家成员扛起或装入任意运输容器（空投舱/任务或玩家穿梭机/gravship 等）期间 pawn 会离开地图（DeSpawn）且不世界化——一律视为押送「待定」，不判失踪也不计离图**；落定后再按实际位置/归属判定：落玩家据点继续、落他派系/无人地则失败）；
  3. 押至玩家据点后发 `huntExtradite` → 复用 `Util_TransportShip_Pickup`（requiredPawns=$wantedPawns → 落点自动=囚犯所在玩家地图；owningFaction=公会；`leaveDelayTicks=120000`(2 天窗口)；`leaveImmediatelyWhenSatisfied`）→ `pickupShipThing.Arrived` 信（提示把囚犯抬上船：倒地或囚犯床上可被殖民者抬运）；
  4. `SentSatisfied`（活犯登机起飞）→ **×2 结算**（伟业值 ×2 + 升级点 +20；通缉犯 `Take` 出容器后 despawn discard，**不改派系**）；`SentUnsatisfied`（2 天窗口满仍存活未登机）→ 失败；
  5. 死亡（任意时点/原因）→ 普通结算（押解窗口内死亡 → `quest.End` 令 util 的 cleanup 直接送走穿梭机）；招募/奴役（Faction==玩家）或活着失踪（不在窝点图/玩家远行队/玩家据点=被遗弃）→ 失败。
  - 判定依据：`Pawn.ThreatDisabled`、`Pawn.IsPrisonerOfColony`、`CaravanUtility.GetCaravan`、`Pawn.CarriedBy`（被扛起时 `ParentHolder` 为搬运者 `Pawn_CarryTracker`、`Spawned=false`）、`FloatMenuOptionProvider_CarryToShuttle`（囚犯倒下/床上可抬运，登机 = `CompShuttle.IsAllowedNow` 的 required 无条件放行通道）。押送合法性 = 显式位置（窝点/家图+玩家囚犯/玩家远行队/被玩家扛）+ 运输容器待定（落定再判）+ 无主世界 pawn（失踪）。
  - **通缉犯目标识别**：进窝点时发「发现通缉犯」信（点名 + `GlobalTargetInfo` 可跳转）；主部件 `QuestLookTargets` 常驻指向通缉犯；任务描述以 `[wanted_nameDef]` 点名（slate 键 `wanted`）。
  - **玩家自有载具（Odyssey）**：玩家穿梭机 = `Ship_PassengerShuttle`（playerShuttle：CompShuttle + TransportShip + 世界对象），乘客装舱后随船在世界飞行，**不世界化成远行队**；gravship 同理。空投/自有载具一律「容器待定、落定按地图归属判」：落玩家据点继续押解、落他派系/无人地失败。
- **世界 pawn 清理（PawnDiscardDecideMode）**：`Decide`＝入世界池交系统按需回收；`KeepForever`＝强制保留（供后续引用）；`Discard`＝立即销毁。任务清理默认 `Decide`。
- **原版 API 参考**：临时成员（lodger/helper）判定与声明式 ExtraFaction、`SetFaction` 行为、远行队/穿梭机可登机过滤、离场自动归位等反编译调研 → `C-05-原版API简述.md`。
- **「物资押运」流程（样板）**：强制任务，使者出场即接取（12 天限时）。选点 = 世界中**既有**定居点 A/B（中立/友好 + 与玩家据点三边 ≤8 格；`GuildQuestGenerator.Available()` 预筛，凑不出组合则静默不发布，根节点 `TestRunInt` 兜底 `Log.Error` 红字）；**全程不进定居点地图**——远行队停在 A/B 的世界层格子，经定居点交互 comp（`WorldObjectComp_SupplyEscort`，props 经 Patch 注入 `SettlementDef.comps`，原版 `TradeRequestComp` 同款）出按钮：
  1. **领取**：`BuildManifest` 从 A 的 `TraderKind.stockGenerators` 现生成清单（同 def 合并；过滤可卖 / 单价 ≤100 / 不腐烂 / 无需材质且无品质 / 非建筑块堆），凑到 **300~600kg 随机**目标总重 → 按 `stackLimit` 拆堆发放；超重则按清单实际重量弹确认窗（确认=硬塞，取消=可再点）。清单存 `manifest`（`List<ThingDefCountClass>`，Scribe Deep），`pending` = 其副本；
  2. **押运途中伏击**：`QuestPart_SupplyEscortAmbush` 每 1000 tick 扫「以 A、B 为圆心、AB 距离为半径」双圆内的**任意玩家远行队**，间隔 2~4 天、上限 2 次，冷却自领取当拍起算；沿用原版 `IncidentDef Ambush`（`forced` 下须自行 `CaravanIncidentUtility.CanFireIncidentWhichWantsToGenerateMapAt` 校验，tile 被定居点占用时跳过重试）；
  3. **分批交付**：`TakePartial` 逐项取 `min(背包现有, 剩余需求)` 扣除（跨堆 `SplitOff`/`Destroy`），`SubtractPending` 递减；未交齐（含一件未交）发信列「本次交付 + 尚缺」，`pending` 清空才结算（快照 B 格远行队内受恩惠成员 → 伟业值 + `rewardsReady` → 晋升评级）；
  4. **失败**：12 天未交齐 → part 发 `escortTimeout` → XML 侧信件 + `QuestNode_RankUpFailed`（1~5 天冷却重发）+ `End Fail`。**不追踪物资实例来源**（可用自备同种同量补齐），但**未领取即无清单、无法交付**。
  5. **统一生成入口**：所有 `GuildQuestGenerator` 一律经 `GuildQuestGenerator.Create(def)` 构造（绑定 def），漏绑会导致 Category/Type 静默为 null（见 B-04 BUG-017）。
- **「难民安置」流程（样板）**：强制任务（Explorer / 评级达标自动接取）。全程在**玩家据点地图**、无站点，是「外部定点袭击 + 存活率 KPI」型任务（与原版难民事件的设计差异见 `plans/难民安置任务开发计划.md`）：
  1. **根节点**：点数 → 人数 `Clamp(1+floor(points/1000),1,10)`；`FactionGenerator.NewGeneratedFactionWithRelations` 现生成**临时隐藏难民派系**（`OutlanderRefugee`、`temporary=true`、与原版难民一致）；`RandomEnemyFaction` 选定袭击派系并**与难民派系设为敌对**（追杀者叙事）；slate 出 `victims / refugeeFaction / raiderFaction / raidPoints(=points×1.2) / totalExploits`。
  2. **装配节点**（须排在 `Util_TransportShip_Pickup` 之后，以便读取 `pickupShipThing`）：`QuestPart_ExtraFaction(MiniFaction, inSignalEnable=接取信号)` 先入队——**必须先于到访加入**（`Pawn.SetFaction` 里「非 lodger 才 ChangeKind」，否则难民 kind 会被改成殖民者）；`quest.PawnsArrive(joinPlayer:true)` 边缘走入并当拍 `SetFaction(玩家)`（**inSignal 必须显式传 `quest.InitiateSignal`**：根层 slate 没有 `inSignal` 变量，缺省取值静默为 null → 部件永不触发）；`SetAllApparelLocked` + `AddMemoryThought(OtherTravelerDied / OtherTravelerSurgicallyViolated)`（两者均为原版难民同款，且未被 `doNotApplyToQuestLodgers` 过滤，lodger 同样受影响）；每名难民一件 `PawnJoinOffer`（心情 ≥50% 按 MTB 发抉择信，`outSignalPawnAccepted` 汇总为 `inSignalsJoinAccepted` 并回填 ExtraFaction 的 `inSignalsRemovePawn`）。
  3. **停留期**（`QuestPart_RefugeeResettle`，250 tick 节流）：到场当拍施加随机受伤（`TakeDamage(DamageInfo(HealthUtility.RandomViolenceDamageType(), 4~12))` 随机部位 1~3 次、25% 追加 `DamageUntilDowned` 倒地）→ 袭击排程（首发 3~5 天、其后间隔 3~5 天、共 2 次；`IncidentDefOf.RaidEnemy` + `IncidentParms{forced, quest, points, faction}` + `Worker.TryExecute`；**`TryExecute` 不经过 `CanFireNow`**，关「大威胁」难度须自行跳过，且实际强度会再乘到达方式/策略的点数曲线）。
  4. **劝加入**：接受 → 移出 `refugees`、记入 `adopted`、**`CompShuttle.requiredPawns.Remove(pawn)`**（起飞达标判定不再等他）、解脱 MiniFaction 标记（转正；依赖 ExtraFaction 显式 Enable 才能收到移除信号）；**全部未死者都转正 → 直接结算成功、不召唤穿梭机**。
  5. **离场**：第 15 天发 `refugeeEvacuate` → `Util_TransportShip_Pickup`（`leaveDelayTicks=120000`＝2 天、`acceptColonists=false` 仅名单可登机）；该 util 的船与 job 全挂在**内层信号**上（`QuestNode_Signal` 的 `OuterNodeCompleted`）→ **不发信号船永不降落**；信件只在 `pickupShipThing.Spawned`（落地）发一次。
  6. **结算**：`SentSatisfied / SentUnsatisfied` → 存活 = 登机数 + 已转正数，`ratio = 存活 / 生成总数` → `DistributeExploits(baseExploits × ratio)` + `GainPoints(category, 10)` → `rewardsReady` → `QuestNode_RankUpComplete` + `End Success`；未登机且未转正者视为失踪（转中立 → `MakePawnsLeave` 自行离图）。**当拍必须先把仍在机舱内的登机者归还原派系**（`Sent*` 当拍成员尚未转移，漏做会连带延迟回报子任务找不到 `rewardGiver`，见 B-04 BUG-018）。
  7. **失败线**（囚禁/奴役、二次有害手术 `victims.SurgeryViolation`、全灭、无人生还）：图上存活难民（**含已被劝加入者**）一并转中立后自行离图，**唯一例外是被囚禁/奴役的受害者本人留在玩家手中**；失败走 `QuestNode_RankUpFailed`（3~5 天冷却后自动重发使者）。
  8. **信号登记要点**：`victims.SurgeryViolation` 由 `RecipeWorker.ReportViolation` 从被手术者广播（`IsViolationOnPawn` 对 lodger 特意放行 → 玩家对难民动违规手术必触发），生成期调用一次 `HardcodedSignalWithQuestID("victims.SurgeryViolation")` 即顺带完成 `victims` 名单的 questTag 登记。

### 伟业（Feat）

四层流水线：**检测**（`Find.BattleLog` + `Patch_FeatContribution`）→ **分析**（`FeatContext` 的成员派生量）→ **判定**（`FeatTraitDef.Judger` 方法驱动）→ **记录**（`FeatRecord` 写入 `Hediff_Pharna.feats`）。

- **数据层**（`FeatTraitDef.cs`，内含四个类型）：`FeatTraitDef` 只持 `multiplier` / `judgerClass` / `displayOrder`；`FeatContext` 装敌方 / 我方两个 Pawn 列表 + 贡献表，派生量以**成员方法**提供（`Threat` / `MaxCombatPower` / `DefeatedCount` / `DownedCount` / `ContributionOf` / `TotalContribution` / `EnemyDamageTotal`）；`FeatTraitJudger` 是判定器基类 + 统一工厂 `Create(def)`；`FeatRecord` 是记录（含 `usedForLevel`）。
- **规则层**（`FeatTraitJudgers.cs`）：每个性质一个判定器类，阈值写在类内 const；判定只看战斗事实，不看任务来源。
- **结算层**（`FeatUtility`）：取战斗事实 → 逐 Def 判定并累乘系数 → 按贡献分摊到个人 → 过九档阈值表得 `tier`；判定异常被逐条捕获（单个判定失败不影响整场结算）。
- **扫描器**（`GameComponent_FeatTracker`）：每 250 tick 扫 `BattleLog.Battles`；沿 `AbsorbedBy` 取末端、`resolved` 列表去重；**结算前先做合并重新归属**（`RenormalizeContributions`，用 `pawn.records.BattleActive` 反推）、结算后清该场贡献条目并清孤儿条目。
- **贡献三路径**：`dealt × 1.0 + taken × 0.5 + support × 1.0`（`DamageWeight` / `TakenWeight` / `SupportWeight`），只记我方、只认"我方 ↔ 敌方"之间的伤害。
- **分摊分母**：`TotalContribution()` = **敌方承受的全部伤害**（`enemyTaken`，不分来源：我方 Pawn / 炮塔 / 商队 / 陷阱 / 环境）+ 我方参战者 `taken × 0.5` + 我方参战者 `support × 1.0`；我方 Pawn 的 `dealt` 已含在敌方受损项内、**不重复计入**，因此 `share = ContributionOf(p) / TotalContribution() ≤ 1`。
- **支援贡献（support）**：三条来源——① 立即型治疗走 `HealHelper`（治愈 / 包扎 / 恢复部位三个工具方法内按真实量上报，末位 `Pawn healer` 参数归因，权重 `HealWeight(1.0)` / `TendWeight(0.3)` / `RestoreWeight(0.3)`）；② 持续型效果（愈合光环 / 疼痛抑制 / 嘲讽）挂 `HediffComp_FeatSupport`，按**实际生效 tick** 累计、每 60 tick 上报一次，贡献度写在 XML 的 `<supportPerSecond>`；③ 无 Hediff 载体的控制（时停 / 光球眩晕）由施加点按 `ControlPerSecond` 折算。治疗与增益均**只计作用于他人**者（自我治疗 / 自我增益由 `HealHelper.ReportSupport` 的 `healer == target` 过滤），嘲讽以 XML 的 `<allowSelf>true</allowSelf>` 为唯一例外。
- **战斗名**：结算时取原版 `Battle.GetName()` 快照进 `FeatRecord.battleName`（该名称为按需生成、每新增一条日志即被清空的缓存，且 `Battle` 只留 20 场，事后不可反查）；取名包 try-catch，取不到时 UI 显示占位词。
- **结算报告**：每次结算向 `Player.log` 输出一份明细（`LogResolveReport`）——战斗名、战斗事实（敌方人数 / 战力 / 最强单体 / 倒下数，我方人数 / 倒地数 / 参与者数）、性质判定与系数乘积、分摊分母的构成、以及**逐人的三类贡献**（输出 / 承伤折算 / 支援）与占比、个人得分、档位。只有「我方有受恩惠者参与且敌人非空」的战斗才会进入结算与输出。
- **升华衔接**：`Hediff_Pharna.AvailableFeat()` 取满足 `tier >= level` 且未使用的**最低档**伟业，`Ascend()` 写入 `usedForLevel`（每件伟业只能用一次）。

### 恩惠页签（ITab_Pawn_Pharna）

Pawn 级只读面板，四个分区：能力 / 发展能力 / 技能·魔法 / 伟业。

- **注册**：`Patches/ITabs_Pharna.xml` 往 `BasePawn.inspectorTabs`（`List<Type>`）追加类型；非受恩惠者由 `ITab.IsVisible` 隐藏。
- **卡片语言**：分区卡走 `UI_GroupBox.DrawOutlinedCardBg`，为**标签框式**——填充与边框同域（自标题中线起到底部），上边框下移至标题中线、左右边框自该线起画到底，标题左内缩并**截断该段上边框**后以纯白 `Medium` 压在其上（淡暖金 `UI_Palette.SectionBorder` 描边 2px，无标题底色）；条目卡一律不描边，只靠"深底 + 左侧色条"区分——技能 / 魔法 / 发展能力按稀有度，伟业按 tier；伟业卡未使用 = 原底 + 亮色条、已使用 = 档位色淡填充 + 半透明色条。
- **表格感**：六维行与发展能力行的偶数行叠 `UI_Palette.RowStripe`；技能 / 魔法两栏不做交错。
- **着色依据**：发展能力 / 技能 / 魔法按**稀有度**（`IAscendReward.RarityColor`，色值取自 `UI_Palette`），伟业按**tier** 九档色表（`UI_Palette.TierColors`）；六维行评级文字用暖金 `UI_Palette.Accent`、数值用浅灰 `UI_Palette.TextValue`。
- **增速衰减色**：`Hediff_Pharna.GetGrowthDecay(type)` 返回双衰减系数（1 = 无衰减），**进度条**随衰减由白转暖色（`Color.Lerp(白, UI_Palette.Decay, 1 - decay)`），并叠 `Hediff_Pharna.AscendStatusThreshold` 升华门槛刻度线（未达成暖金、已达成弱灰）。
- **六维行 tooltip**：当前 / 潜在 / 总计（`GetCurrentStatus` / `GetPotential` / `GetFullStatus`）与成长效率百分比。
- **只读**：操作入口（技能 / 魔法释放、魔力池开关）仍在 Gizmo。

## 三、关键架构决策

| 决策 | 理由 |
|---|---|
| 魔法继承原版 `Ability` 体系 | 复用灵能 UI/技能栏/熵资源，减少重复造轮子 |
| 咏唱词用相机烘焙为贴图 | 可靠渲染文字，避免字体图集 CPU 读取问题 |
| 发展能力用 StatPart 按 StatDef 注入 | 与 Defs 配置对齐，数值系数集中可调 |
| 公会任务用 QuestNode/QuestPart | 与原版任务系统一致，便于扩展新任务类型 |
| 任务动作一律 QuestPart 化、监听 rewardsReady/失败信号 | QuestNode 在任务生成期执行，直接副作用会把晋升/失败重发提前到建任务瞬间；运行时动作必须由 QuestPart 承接 |
| 使者全局单槽 + 强制"出场即自动接取" | 同一时刻至多一个待处理使者杜绝叠加；强制任务不依赖玩家对话，根除"拖对话→使者离场→永久卡死" |
| 强制失败写入 retryTick 冷却、轮询到期重发 | 失败/超时后 3~5 天自动重新发布，评级升级链路不再卡死 |
| 任务点数统一 QuestUtilities | 财富走原版基准避免双算；恩惠成长按全殖民地总等级+总经验补偿；强制单独 ×1.5；点数可直接用于站点/袭击 |
| 任务三件套范式：根节点 + 过程 part + 奖励/评级部件 | 线性任务用根节点 + 站点型专用奖励 part（据点清剿 `SiteClearanceReward`）；多阶段/复杂任务由 QuestPartActivable 状态机承载业务（紧急救援为样板），各任务根/过程自实现但规格相似。任务侧奖励统一出口为 `GameComponent_FamiliaRankTracker.GainPoints`（升级点数；伟业已改为按战斗事实独立结算，不经任务发放），**不设通用奖励 part**（通用 part 需依赖 XML 节点顺序才能读到动态金额，属隐式耦合） |
| 奖励名单化：威胁清除时点快照参与者、结算按名单 | 参与者在任务达成时点确定（站点在场），避免结算时人员已分散而误发；日常/强制/救援共用 |
| 公会隐藏派系加载时补建（EnsureGuildFaction） | FactionDef 各 count=0 时世界无实例，`FirstFactionOfDef` 恒 null → 使者无法生成；惰性补建隐藏派系并保持与玩家中立 |
| 技能用 charge(充能)+回充冷却而非单冷却闸 | 支持多段/击杀重置类技能，展示当前充能数，语义更直观 |
| 技能 effect 生命周期用 HediffComp 回调驱动 active | 由效果 Hediff 存在与否决定冷却暂停，避免运行时手动维护集合 |
| 技能状态指示用基类+comp 反查；魔法用接口默认实现 | 技能状态为普遍需求(都进 pharna.skills 统一框架)，魔法持续展示为少数魔法 → 按普及度分治 |
| 跨存档运行时集合在 ExposeData PostLoadInit 重建 | 静态集合不随 Scribe 序列化，读档后须从可持久化数据(active/hediff)重建 |
| 击退用 GameComponent 逐 tick 位移 + StunFor 禁用寻路 | 原版无位移型击退 API；每 tick 同步 pather(Notify_Teleported resetTweenedPos:false)防闪回，stun 使 PatherTick 短路 |
| 直线路径索敌抽为 RangeUtilities 公共静态工具 | 居合/夹枪冲锋/超电磁炮的 GetHitCells/GetEnemiesOnPath/GetDest 逻辑重复，抽离统一实现（含可选 validator 做实心墙/可通行拦截） |
| 强化主动技能(按次数)用 SkillInEffect + DisappearsWithCounter 双 comp 驱动 active/计数 | 效果按次数而非固定 duration 结束；计数归零经 CompShouldRemove 自动移除，冷却/active 由既有生命周期闭合 |
| 贯穿/伤害改写在 Verb_LaunchProjectile.TryCastShot Prefix 返回 false | 屏蔽原弹单点命中、以即时贯穿结算替代，避免原弹与贯穿双伤叠加 |
| GetActiveSkill 泛型查询(取 active 技能)单放 PharnaUtility | 区别于嘲讽 Provokers 静态集合(遍历周围多嘲讽者取最近)；前者是"pawn 自身 active 技能"单体语义，勿混用 |
| 押送判定：pawn 存在性 ≠ `Spawned` | 搬运/装载/飞行中 `Spawned=false` 不代表失踪；按 `Spawned/IsWorldPawn/CarriedBy/ParentHolder` 组合判定，容器态 = 押送待定、落定再判，防"抬一下就误判失败" |
| 罪犯追捕结算口径：死亡=普通、招奴/失踪/窗口未登机=失败、活犯押走=×2（含升级点）、押走即 despawn discard | 用户规则定稿：单犯 + 真囚犯（guest prisoner）；押解成败决定奖励档位；不修改囚犯派系、随船后直接销毁 |
| 威胁清除前不即时结算目标死亡（`Notify_PawnKilled` 限定 stage） | 防"只杀通缉犯即提前成功"；目标死亡统一在威胁清除分流时裁决 |
| 物资押运：世界层停留交互（定居点 comp）而非进图 | 避免"进定居点地图 → 离图地图移除 → 货物丢失"的连锁坑；`Settlement` 不可改，交互只能经 comp，而 comp 无实例级 AddComp → 挂 def 级（原版 TradeRequestComp 同款） |
| 物资押运达标口径：清单相等（非按重量）+ 分批交付 | 领取当拍生成 def+数量清单并持久化，交付逐项核验、只扣清单内物品；未交齐发信提示缺口；不追踪实例来源（可自备同种同量补齐） |
| 任务可用性预筛放 `GuildQuestGenerator.Available()`（静默）+ 根节点 `TestRunInt` 兜底红字 | 避免"生成失败 → 每 1000 tick 刷红字"；只有真异常路径才打红字 |
